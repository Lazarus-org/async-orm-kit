# ADR-003: Explicit Session Management

**Status:** Accepted and implemented in Phase 2
**Date:** 2026-03-30

## Context

Session management controls connection lifecycle, identity-map state, and
transaction boundaries. Implicit or task-local session lookup is difficult to
reason about in asynchronous applications.

## Decision

All database operations receive an explicit SQLAlchemy `AsyncSession`. The
application creates the engine and session factory, controls transaction scopes,
and closes sessions. The ORM does not maintain a global session.

## Example

```python
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

engine = create_async_engine("sqlite+aiosqlite:///./app.db")
SessionFactory = async_sessionmaker(engine, expire_on_commit=False)

async with SessionFactory() as session:
    async with session.begin():
        users = await User.objects.filter(session, is_active=True)
```

## Transaction ownership

The application owns transaction boundaries. Model saves/deletes and QuerySet
mutations flush or execute within the active transaction but never commit or roll
back it. After a database flush error, the caller must roll back the transaction
before reusing the session, following SQLAlchemy's normal failed-transaction rules.

## Consequences

- Session ownership is visible in method signatures.
- Applications can use dependency injection and their own session factories.
- Tests can supply isolated sessions.
- The ORM does not dictate engine URLs, pooling, or transaction policy.
