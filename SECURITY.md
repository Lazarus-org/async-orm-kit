# Security policy

This project is in development. Do not report suspected vulnerabilities in a
public issue. Once the standalone GitHub repository is established, maintainers
should enable GitHub private vulnerability reporting and configure a monitored
security contact. Until then, security contact details are not yet verified.

When reporting a vulnerability, include affected versions, a minimal reproduction,
impact, and any suggested mitigation. Do not include real credentials or private
production data.

Reviewers should avoid sharing connection strings, signed storage URLs, request
payloads, or raw database driver exceptions in public issues. The release
workflow requires repository and PyPI publication controls to be verified
separately; successful YAML parsing is not evidence of protection settings.
